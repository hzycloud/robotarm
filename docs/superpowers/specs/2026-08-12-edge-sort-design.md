# Edge-Sort 端侧闭环分拣系统：设计文档

- 日期：2026-08-12
- 状态：已获用户确认（设计第 1/2/3 部分），待用户终审
- 目标：三个月内产出一篇中科院二区 SCI 论文（低成本发表），并为第二、三篇论文预留资产

## 1. 背景与目标

### 1.1 基线论文

参考基线：*Integrating Tiny Machine Learning and Edge Computing for Real-Time Object Recognition in Industrial Robotic Arms*（Eng. Proc. 2025, 92, 74）。该文为会议论文集论文，非 SCI，其系统与指标是本文的对照基准。

基线系统的七个可攻击点：

1. 识别平均耗时 7.6 秒（开环、无实时性）；
2. 单次抓取平均 14.6 秒；
3. 无闭环纠错机制，抓取失败即失败；
4. Edge Impulse 黑盒工具链，方法不可完全复现；
5. 仅 4 类简单几何形状，任务复杂度低；
6. 数据集仅 690 张图片；
7. UR5 平台成本高，不适合低成本升级叙事。

### 1.2 硬件与计算资产

- Hiwonder SO-ARM101 LeRobot 豪华版：leader（示教）+ follower（执行）双臂，6 自由度，12×STS3215 总线舵机（30 kg·cm，磁编码反馈），BusLinker V3.0 调试板，底盘支架齐全。
- 双摄像头：腕部 30 万像素相机（可装夹爪，eye-in-hand）+ 外部 200 万像素相机（固定底座、可移动，eye-to-hand）。
- Raspberry Pi 5 8GB（边缘部署/推理）。
- Raspberry Pi Debug Probe（本期用于串口/调试工具，正式出场在第二篇论文）。
- NVIDIA A100（训练算力）。

### 1.3 硬约束

- 时间：三个月内完成第一篇论文投稿；用户每周可投入约 10–15 小时。
- 分区：中科院二区及以上。
- 费用：版面费越低越好（排除全 OA 高 APC 期刊，如 MDPI 与 Discover Computing）。
- 技能基线：仅基础 Linux 操作，无 PyTorch/ROS/机器人学实操经验，需内置学习爬坡期。
- 任务：桌面小物体分拣（玩具、积木、螺丝/螺母、小杯等，最终物体清单以实际可抓取性为准）。

## 2. 论文路线：B+A 合并稿

主攻系统+闭环型（路线 B），并将轻量策略部署（路线 A）作为方法章节合并进同一篇论文。异构实时架构（路线 C）留给第二篇。

### 2.1 工作标题

*Edge-Sort: Closed-Loop Desktop Sorting via Tiny Distilled ACT Policies on a Low-Cost Edge Robotic Arm*

### 2.2 四个贡献点

1. **TinyACT 轻量策略**：以标准 ACT（ResNet18 骨干 + Transformer）为教师，训练 MobileNetV3-Small 级轻量学生网络，知识蒸馏 + int8 量化（QAT/PTQ，导出 ONNX/TFLite），部署到 Pi 5 CPU，目标单步推理 ≤200 ms。
2. **闭环抓取验证器**：腕部相机 + int8 轻量二分类器（抓到/没抓到），策略执行后自动验证，失败触发重抓；将开环演示系统升级为闭环自主系统。
3. **能耗-时延联合基准**：USB 功率计测量 Pi 5 与舵机总线真实功耗，报告每件分拣能耗（J/件）、周期时间（s/件）、推理时延分解（图像采集/预处理/策略/验证/串口通信），并与桌面 GPU 部署对比。
4. **开源数据资产**：SO-Sort 数据集（LeRobot 格式，双相机同步，80+ 条演示，3–4 类物体），发布至 Hugging Face 与 GitHub，保证可复现性。

### 2.3 任务定义

桌面 3–4 类小物体随机位姿摆放，机械臂逐件抓取并按类别放入目标槽/区域。成功率按每件独立试次计，报告 50–100 次试次的统计结果。物体清单后续按实际可抓取性调整（螺丝建议 M3 以上螺母/大头螺丝）。

## 3. 系统架构

三层结构：

- 感知/决策层：Pi 5 8GB，双 UVC 相机（腕部 30W + 外部 200W），TinyACT 策略推理 + 验证器推理，任务调度与重试逻辑。
- 执行层：SO-ARM101 从臂 + 6×STS3215 总线舵机，USB 串口下发关节目标角/速度，夹爪开合；BusLinker 用于标定与状态监控。
- 训练/数据层：leader-follower 遥操作采集 → LeRobot parquet + 视频数据集 → A100 训练教师/学生 → 导出 int8 模型回传 Pi 5。

数据流（一次分拣闭环）：

1. 外部相机获取场景 → TinyACT 输出动作块；
2. 执行层按动作块驱动舵机（夹爪运动）；
3. 腕部相机拍摄抓取结果 → 验证器判定成功/失败；
4. 成功 → 放入目标槽并记录；失败 → 松开重抓（同目标最多 N 次，连续失败转下一个目标）；
5. 全过程记录时间戳、关节状态、功耗数据。

## 4. 方法细节

### 4.1 数据采集协议

- 演示数量：80–100 条，覆盖随机位姿与多物体组合。
- 采样：双相机同步 + 关节角度 + 夹爪开合，LeRobot 默认频率（约 30–50 Hz）。
- 演示标准化：轨迹平滑、速度一致、物体摆位模板化，保证数据质量。
- 采集节奏：每天 20–30 条，W3–W4 完成。

### 4.2 教师与学生模型

- 教师：标准 ACT（LeRobot 官方实现），ResNet18 骨干，双相机输入（可先 320×240 降低部署压力）。
- 学生：MobileNetV3-Small 级骨干 + 缩减 Transformer，动作块长度可缩（如 50→25）。
- 蒸馏：教师生成伪动作监督学生（动作级蒸馏），可选特征级蒸馏；训练损失 = 学生自身 MSE + λ×蒸馏损失。
- 量化：先 PTQ 摸底，若精度损失大则改 QAT；导出 ONNX Runtime int8 或 TFLite int8，报告模型体积与精度损失。

### 4.3 验证器与闭环重试

- 输入：腕部相机在抓取动作结束后的单帧（或多帧投票）。
- 模型：MobileNetV2（0.1x–0.25x）级二分类器，int8 部署，阈值在校验集上标定。
- 重试逻辑：验证为失败 → 松开夹爪 → 同目标重新推理重抓，最多 N=2 次；仍失败则记录并切换目标。
- 备用验证信号：舵机电流/负载反馈（STS 总线可读）作为第二信号，实验后期若时间允许再接入。

### 4.4 错误处理与安全

- 关节限位保护 + 简单安全停止（越限即停）。
- 目标不可达/连续失败：跳过并记录原因。
- 舵机过热/失步：通过总线状态监控检测，日志告警。
- 相机遮挡/光照变化：训练数据增强（亮度、噪声、裁剪、旋转），外部相机固定位姿。

## 5. 实验设计

### 5.1 必报指标

- 单件分拣成功率（%）
- 周期时间（s/件）
- 单步推理时延（ms）及端到端时延分解
- 每件能耗（J/件）
- 模型体积（MB）与量化精度损失

### 5.2 实验矩阵（每个配置 ≥30–50 次真实试次，报告均值±标准差）

| 对比维度 | 配置 | 主要指标 |
|---|---|---|
| 模型压缩 | 教师 ACT（A100）→ 学生 TinyACT → int8 量化版 | 成功率、推理时延、模型体积 |
| 闭环增益 | 开环（无验证器）vs 闭环（验证器+重试） | 成功率提升幅度 |
| 感知模态 | 仅外部相机 vs 双相机 | 抓取成功率 |
| 文献基线 | 基线论文（7.6 s / 14.6 s / 99%） | 周期时间、时延数量级对比（注明平台差异，仅做功能级对比） |

### 5.3 统计方法

每个配置独立随机重摆物体，试次间物体位姿独立；报告均值±标准差；主对比（开环 vs 闭环、教师 vs 学生）用配对/独立样本检验（如 Wilcoxon 符号秩检验）。

## 7. 风险与预案

1. ACT 在 Pi 5 上跑不动 → 降分辨率/缩动作块长度/换更小骨干；最坏退路为“视觉伺服+经典控制”方案，论文降级为系统+闭环验证叙事，仍可投 Sensors Journal。
2. 抓取失败率高 → 物体选型放宽（大螺母/大玩具）；验证器+重试兜底；后期接入舵机电流反馈。
3. 数据采集慢 → 演示协议标准化 + 摆位模板；每天固定 20–30 条。
4. 时间透支 → 砍掉“单相机 vs 双相机”消融；写作从 W6 强制并行。
5. 蒸馏收益不明显 → 主创新叙事回归闭环验证器，蒸馏/量化作为部署方法论工具呈现。
